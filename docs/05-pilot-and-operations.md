# 파일럿과 운영 검증

테스트할 워크스페이스와 채널, 사용 계정을 먼저 확인합니다. 같은 이름의 과거 환경으로 자동 전송하지 않습니다. 가상 사례를 소수 사용하고 실제 고객 발송과 데이터 변경은 하지 않습니다.

1. 일반 A 요청이 불필요한 CX 호출 없이 처리되는지 확인합니다.
2. A에게만 CS 질문을 보내 실제 CX의 의견과 A의 정리가 같은 스레드에 남는지 확인합니다.
3. CX에게만 조율이 필요한 질문을 보내 실제 A 보고와 필요 시 사람 태그를 확인합니다.
4. 담당자 답변을 같은 스레드에 남겼을 때 A가 이어가는지 확인합니다.
5. 미허용 사용자와 다른 봇의 입력이 거부되는지 확인합니다.
6. 두 프로필의 재시작, 절전 영향과 재부팅 후 복구를 확인합니다.

실제 업무 스킬을 받으면 대표 사례와 이전 업무 결과를 비교하고 1주간 병행합니다. 실패 시 입력, 기대 결과, 실제 결과와 원인을 기록합니다. 재시도한다고 전체 봇과 전체 사용자를 허용하지 않습니다.

API fallback은 비활성입니다. 구독 인증과 한도 문제는 그 상태로 보고합니다. 정확한 사용량 차감과 장기 OAuth 갱신은 별도로 확인하며, 구독 플랜만으로 무제한 운영을 보장하지 않습니다.

상태 확인과 재시작은 [운영 가이드](../OPERATIONS.md), 기능 변경은 [요구사항 변경](13-changing-requirements.md)을 참고합니다.
