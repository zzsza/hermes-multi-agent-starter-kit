# 업무 스킬과 승인 경계

기존 채팅방 한 개를 업무 스킬 한 개로 이식합니다. 운영자에게 원본 프롬프트와 대표 입력과 출력 세 쌍을 받습니다. 상황, 동작, 결과 형식, 모호할 때의 질문, 금지 행동과 예시를 정리합니다.

자료가 없다면 [수집 양식](../templates/process-intake.md)과 미활성 스킬 양식만 사용합니다. 고객사 정책과 사례를 지어내지 않습니다. 실제 스킬을 등록할 때 [환불], [리포트]처럼 합의한 요청 접두어를 SOUL과 채널 안내에 함께 적습니다.

현재 모델 도구에는 고객 발송, 환불 실행, CRM과 DB 수정, 파일 삭제와 터미널 실행이 없습니다. 사람 승인 답변이 있어도 해당 기능이 자동으로 생기지는 않습니다. 실제 실행 도구를 추가할 때는 승인자, 적용 대상과 승인 범위를 별도로 구현하고 시험합니다.

터미널을 도입한다면 대상 서버에서 Docker daemon과 격리 실행 가능 여부부터 확인합니다. 템플릿의 docker backend 설정만으로 격리가 작동한다고 판단하지 않습니다.

모델의 사용자 메모리를 꺼도 세션 DB와 로그는 별도로 남을 수 있습니다. 실제 고객 정보 사용 전에 보관 기간, 접근 권한과 백업을 정합니다. 비밀번호, 키와 토큰은 Slack 입력과 업무 사례에 포함하지 않습니다.
