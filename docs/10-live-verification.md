# 검증 기준과 참고 결과

이 문서는 개발 단계의 확인 범위와 새 환경에서 다시 해야 할 검사를 구분합니다. 개인 계정, 설치자의 상태, Slack 식별자와 과거 스레드 링크는 포함하지 않습니다. 새 컴퓨터가 설치되었거나 로그인되어 있다는 뜻이 아닙니다.

## 이전 개발 단계에서 확인한 것

Hermes v0.13.0 source 설치와 전용 Python 3.11.13에서 두 프로필과 Slack 앱으로 시험했습니다.

| 시험 | 확인 결과 |
|---|---|
| 일반 요청 | A가 직접 답하고 불필요한 CX 호출 없음 |
| A 시작 CS 확인 | 사람이 A만 멘션, 실제 별도 CX에 질문, CX 결과를 받아 A 정리 |
| 기존 스레드 후속 답변 | 사람이 A를 다시 멘션하지 않아도 이어서 처리 |
| 새로운 정보에 따른 재확인 | 같은 스레드에서 새로운 CX 확인 후 A 정리 |
| 정책 부족 | A가 CX 의견을 받고 같은 스레드의 고정 담당자를 한 번 태그 |
| 담당자 답변 후 처리 | 판단 보류와 확인 항목을 반영해 A가 이어서 정리 |
| 정보 충돌 | 임의로 기록을 선택하지 않고 사람 판단 대기 |
| CX 시작 보고 | 사람이 CX만 멘션, CX가 실제 A에게 보고, A가 담당자 태그 |
| 양방향 경로 공존 | CX 시작 경로 추가 뒤 기존 A 시작 확인도 다시 성공 |

실제 고객 자료와 고객 발송, 환불과 시스템 변경은 시험하지 않았습니다. 업무 정답의 검증과 통신 시험은 별개입니다.

## 코드와 자료 검사

연결과 설치 적용에 대한 기존 15개 단위 테스트는 네트워크 없이 실행했습니다. 허용된 세션과 스레드, 실제 CX 응답 식별, 중복 방지, 임의 멘션 escape, 전송 오류와 timeout 처리, 발신자 기준 왕복 차단, 프로필별 인증 보존과 fallback 비활성을 확인합니다.

배포 압축에는 캐시, 상태 JSON과 인증, 로그, 세션 DB와 private 폴더가 포함되지 않는지도 검사합니다. 정적 검사는 템플릿의 비어 있는 환경 입력값과 안전한 설정, 매니페스트, 문서 링크와 비밀값 패턴을 확인합니다.

## 새 환경에서 다시 확인할 것

- Codex, Tailscale, Aside와 Hermes의 설치와 실제 사용 가능 여부.
- 사용할 계정과 ChatGPT 플랜, 목표 모델과 보조 모델의 실제 호출.
- 지정한 워크스페이스와 테스트 채널, 봇 두 개의 초대와 요청 허용 사용자.
- A 시작과 CX 시작의 실제 계정별 메시지와 동일 스레드 처리.
- 사람 태그와 담당자 후속 답변, 불필요한 재호출 여부.
- 허용되지 않은 사용자와 다른 봇, 관리자 명령 접근 제한.
- 프로필별 OAuth 장기 갱신과 실제 사용량 차감. 토큰 복사 공유는 하지 않음.
- Mac의 절전과 네트워크 중단 영향, 사용자 로그인 이후 서비스 복구와 재부팅 시험.
- 업무 프롬프트와 실제 사례에 따른 정답 비교, 1주 병행 운영.

주 모델 호출 전 인증 오류와 Slack 전체 장애가 나면 사람 태그도 보장할 수 없습니다. 현재 브리지는 장기 영구 작업 큐와 프로세스 재시작을 넘어서는 정확히 한 번 처리 보장을 제공하지 않습니다.

새 환경의 검사 결과는 새 컴퓨터의 private 설치 기록에만 식별자와 함께 남기고, 재배포 문서에는 비밀값과 개인 상태를 옮기지 않습니다. [설치 체크리스트](../SETUP.md)부터 진행합니다.
